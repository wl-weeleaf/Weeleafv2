# Leafy Live — first integrated MVP

Start at `/leafy-live/control` or the Leafy Live link in Leafy's room. This module uses the existing `LeafyCanvas`, shared persona/profile/skills, `/api/livi/chat`, shared approval endpoint, and the existing Danish voice selection and lipsync. No replacement character or AI backend is created.

## Presenter flow

1. Choose a camera, press **Start kamerapreview** and approve the browser permission. The standard room background is selected initially. Select **Hele kamerabilledet** to use the uncropped camera as the scene background and choose Leafy’s placement.
2. Choose a mic and press **Start mikrofon**. Press **Lyt til foredraget** to explicitly send live audio for Corti transcription (using the existing secure token endpoint). If Corti configuration is unavailable, browser speech recognition is used where supported; that fallback may use the browser's default mic and vendor's recognition service.
3. Use **Foredrag**, **Samtale**, or **Leafy tager over**. In Foredrag, final speech starting with `Hej Leafy`, `Hey Leafy` or `Leafy` activates a reply. An isolated wake phrase waits up to eight seconds for the next final utterance. Ordinary lecture speech only enters the context. Samtale waits 4.5 seconds after a final utterance, and limits proactive turns to one per 15 seconds. This is a conservative pause rule, not human turn-taking intelligence.
4. Load images/video/PDF; PDF page text enters the live context. Websites, graphs and other apps can be shown through user-authorised tab/screen sharing. Local videos have explicit play/pause. Add descriptions for images and shared websites: these pixels are not automatically sent to the model. PowerPoint/Keynote should be exported to PDF.
5. Create the audience link/QR. Questions are queued and only explicitly approved questions can be shown or sent to Leafy. The QR can itself be shown in the scene. The audience URL carries a separate token from the stage URL and grants no presenter rights.
6. Start **scene-output**, then open the clean `/leafy-live/stage?session=…&key=…` link on the second screen, in OBS Browser Source, or in another browser. Output is one 1280×720 canvas stream, compositing the room or complete camera background, existing 3D Leafy, media and approved question. No video-meeting boxes or normal app menus appear in this route.
7. Browser TTS does not expose a MediaStream audio track. Microphone audio is mixed into WebRTC immediately. To attempt capture of Leafy's actual existing voice, press **Tilføj browser / systemlyd**, select the Leafy control tab with tab audio, or a supported system audio source. Capture support depends on browser/OS/voice; some native OS voices require OBS desktop audio rather than tab capture. Verify audibility in the receiver before a talk. Do not select a tab that plays the received scene: that creates feedback. Virtual Camera is installed/enabled in OBS, not by this website.
8. Stop ends camera, mic, transcription, WebRTC output and screen/tab capture. A tab/screen share also ends through the browser's own stop-sharing control. Leaving the page closes all resources.

## Layout and animation

AUTO defaults to DUO, places content centrally with actors at the sides, and enlarges Leafy during takeover. Seven presets are available. SceneDirector reserves a question band, uses exponential easing, and constrains the content rectangle while transitioning so it does not cross actors. Leafy uses the existing breathing, idle, expression, voice and mouth layer engine. Scene-directed gaze takes precedence over pointer gaze; presenter speech takes precedence over content/questions. The pointer is mapped from the visible stage, not the offscreen renderer. Native browser lipsync is the existing approximate mode; phoneme-accurate cues require the already supported timed audio provider.

## Transport / data

Same-origin `/api/leafy-live` handles 12-hour sessions, moderated question queues, and WebRTC offer/answer/ICE signaling in existing D1. It stores no video, audio, or lecture transcript. Owner operations require the existing HttpOnly visitor cookie. Audience/viewer tokens are distinct random tokens. Viewer count, message sizes, queue lengths and submission rates are bounded. WebRTC is peer-to-peer with STUN. There is no TURN relay configured: restrictive NAT/firewalls may prevent connection across networks. Same-network or local OBS/browser use is the initial target. Maintain a visible control window, particularly during long presentations, because browsers can throttle hidden tabs.

Transcripts are in memory by default, with a bounded 5,000-entry lecture history. Recent context plus keyword-selected earlier excerpts are provided to the same AI runtime on activation; this is not unlimited model memory. Explicit local persistence/export is opt-in. Stored history is loaded only by clicking **Indlæs tidligere gemt historik**. Camera pixels are only sent to an authorised stage receiver, not to the segmentation vendor. Live STT necessarily sends mic audio to the configured recognition provider. Existing AI tool/artifact/approval stores retain their usual semantics.

## Assets / build

`pnpm dev` and `pnpm build` run `scripts/prepare-live-assets.mjs` first, copying the pinned `@mediapipe/tasks-vision` 0.10.32 runtime and SIMD/no-SIMD WASM into `public/leafy-live`. The 249 KB model is shipped with the module; no segmentation CDN is needed at runtime. The downloadable full source ZIP omits the reproducible MediaPipe runtime binaries to stay within the hosting asset size limit; standard dependency installation and dev/build restores them automatically. Segmentation adapts sampling from 15 FPS / 320px down to 8 FPS / 192px when inference is slow, while the compositor targets 30 FPS. No model/voice secret is put in browser source.

## Verification

Automated checks cover all layout combinations, transitions, wake phrase gating, existing shared core, camera permission structure and audience moderation guards. Production TypeScript/build checks are required. The dedicated worker uses dynamic module import plus the classic `importScripts` context required by MediaPipe 0.10.32’s Emscripten loader. Actual camera segmentation quality, Corti recognition, Danish native voice availability, audio capture/latency, WebRTC NAT behavior and OBS need device testing; no FPS or live-provider result is claimed by these unit tests. There is no public livestream fan-out/CDN, automatic virtual camera install, TURN infrastructure, or full model vision of arbitrary stage pixels in this MVP.

## Stability update

Live transcription and scene reception now accept an AbortSignal. Stopping while Corti authentication or a scene join is pending cannot start recognition or attach a late stream. Corti configuration is accepted once; provider denial and slow-socket buffering close the recorder and socket. Presenter mic tracks remain owned by the camera/microphone controls. Host stop ends all output tracks, aborts polling, and ignores late offers. Receiver setup failure or closing the stage releases its viewer slot and closes its peer; stopped sessions stop polling. Camera-tab and screen-share picker results are discarded and their tracks stopped if the presenter has stopped or left before granting permission. Scene start is guarded against duplicate clicks and can be cancelled while pending.

Long replies are queued as complete, Unicode-safe voice chunks below the existing voice limit. The shared Leafy speech engine exposes whether speech remains queued, so takeover/listening does not finish between chunks. Cancelled AI responses cannot update a newer response. These lifecycle scenarios are tested using real service code with mocked browser devices/transports; they do not replace a physical Corti/camera/OBS test.
